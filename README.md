# 段取り

ローカルで使う、プロジェクトマネジメントと要件定義のサポートツール。
人は「判断」だけを行い、整理と点検は道具に任せる、という考え方で作っています。

設計の根拠と今後の予定は [PLAN.md](PLAN.md) にあります。

## 使い方

Node.js 22.13 以上が必要です。インストールするものはありません。

```sh
npm start        # http://127.0.0.1:4321/ が開く
```

1. プロジェクトの名前を入れる
2. 画面上の欄に、思いついたこと・聞いたこと・頼まれたことを1行で書く（議事録の貼り付けも可）
3. 受付箱で「これは何か」を1つ選ぶ
4. あとはホームの「今日やること」（最大3件）に従う

データは `data/dandori.db`（SQLite）に入ります。外部には何も送りません。

## 要件定義で使う

「要件」の画面で、次のことができます。最初は「練習用のプロジェクト」（プロジェクト名の切り替えから作れます）で試すのが早道です。

- **層に並べる**：目的 → 業務 → システム → 機能。上に辿れない機能（根拠がない）と、下のない業務（抜け）に印が付きます
- **書き方の点検**：「適切に」「必要に応じて」のような言葉を見つけ、問いの形で返します。1クリックで未決として起票できます
- **受け入れ条件**：前提・操作・結果の3つで書きます。「正しく処理される」のような確かめられない結果は指摘されます
- **例外さがしの表**：条件を並べると全組み合わせの表に、状態と出来事を並べると掛け合わせの表になり、空白の数が見えます
- **観点での例外さがし**：17の観点を1つずつ当てます。「何も出なかった」も記録されます
- **書き出し**：憲章の画面の下から、プロジェクト全体を1枚の Markdown にできます

## コーディングエージェントと使う

このリポジトリで Claude Code を開くと、3つの Skill が使えます。どれも結果を「AIの案」として登録し、人が画面で確認するまで決定扱いになりません。

| Skill | 頼み方の例 | すること |
|---|---|---|
| `dandori-capture` | 「この議事録を段取りに取り込んで」 | 文章から要件・未決・決定・リスク・言葉・依頼を切り出す |
| `dandori-review` | 「要件をレビューして」 | 点検し、答えではなく問いを返す |
| `dandori-exceptions` | 「R-7 の例外を洗い出して」 | 表の枠を作り、例外の候補を挙げる（空白は埋めない） |

## コマンドライン

コーディングエージェントからも同じデータを読み書きできます。出力は JSON です。

```sh
./bin/dandori.js help
./bin/dandori.js add "売上の計上先はどちらか？" --type open --owner 社長 --due 2027-08-31
./bin/dandori.js list --type open
./bin/dandori.js next
./bin/dandori.js tree            # 要件を層のツリーで
./bin/dandori.js lint            # 要件の点検
./bin/dandori.js export          # export/ に Markdown を書き出す
./bin/dandori.js sample          # 練習用のプロジェクトを作る
```

`--ai` を付けて足したものは「AIの案」として記録され、人が画面で確認するまで決定扱いになりません。

## テスト

```sh
npm test         # ルールとデータ層

```
