# 例外をさがす

例外は「ありますか」と聞いても出てこない。表にして空白を見せると出てくる。あなたの仕事は **表の枠を作ることと、候補を挙げること** まで。空白を埋める（＝業務としてどうするかを決める）のは人。

## 手順

1. 対象の要件を読む。

   ```sh
   ./bin/dandori.js tree
   ./bin/dandori.js show R-7
   ./bin/dandori.js list --type exception
   ```

2. 表の枠を作る。**セルは埋めない。**

   - **条件の組み合わせ**：1つの場面で、結果を左右する「はい／いいえ」の条件を2〜4個選ぶ。5個が上限（32行）。それ以上は場面を分ける。

     ```sh
     ./bin/dandori.js table R-7 "来店して引き渡すとき" --conditions "期限内,現物あり,本人確認できた" --ai
     ```

   - **状態と出来事**：対象（注文、申請、予約…）が取りうる状態と、起きうる出来事を並べる。出来事には、起きてほしくないもの（取り消し、期限切れ、現物がない、休業）を必ず入れる。

     ```sh
     ./bin/dandori.js table R-5 "取り置き注文の状態" --states "受付済,確保済,準備完了,引渡済,返棚済" --events "来店・引渡,期限到来,客がキャンセル,現物なし判明,臨時休業" --ai
     ```

3. 次の観点を順に当て、**その要件で実際に起きそうなもの** だけを候補にする。一般論は挙げない。

   量（0件・大量・集中）／時間（営業時間外・締め処理中・年に一度の日）／人（不在・権限なし・退職者）／モノ（現物がない・壊れている・入らない）／お金（返品・併用・返金先）／場所（休業・改装・閉鎖）／順番（飛ばす・戻る・二重）／重複（二重予約・同時）／中断（通信断・障害・定期処理と重なる）／取り消し（やめたい・間違い・もう済んだ後）／外部（連携先停止・形式変更・無応答）／制度（税率・法令・保存期限）

   加えて時間軸：毎日・毎週・毎月・年に一度・数年に一度、それぞれ何が起きるか。年次のことは聞かないと出てこない。

4. 候補を登録する。扱い（`handling`）は **付けない**。どう扱うかは人が決める。

   ```sh
   ./bin/dandori.js add "期限が切れた後に、お客様が来店した" --type exception --field viewpoint=time --ai
   ```

   `viewpoint` の値：quantity / time / people / things / money / place / order / duplicate / interrupt / cancel / external / rules / daily / weekly / monthly / yearly / rare

5. 報告する。作った表（空白の数）と、挙げた候補を伝える。2つの表、または表と観点が **同じ穴を指した** ものがあれば、それを最初に伝える（本物の穴である可能性が高い）。最後に、現場に聞くとよい問いを2〜3個添える。聞き方は要約ではなく想起を求める形にする。

   - ×「例外はありますか」→ ○「先週、手順どおりにいかなかったのは何回ありましたか」
   - ×「困っていることは」→ ○「上司に確認しに行くのは、どんなときですか」
   - ○「Excel やメールで別に管理している一覧はありますか」

## 守ること

- 登録は必ず `--ai` を付ける。
- 候補は多くて10件。網羅より、その業務で本当に起きそうなものを選ぶ。
- すべてをシステムで扱う前提で話さない。「人が扱う」「業務を変えて例外をなくす」も選択肢であることを伝える。
