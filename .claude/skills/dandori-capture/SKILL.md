# 議事録やメモを「段取り」に取り込む

貼られた文章から項目を切り出し、CLI で **AIの案** として登録する。人が画面で確認するまで、決まったことには数えられない。

## 守ること

- **必ず `--ai` を付ける。** 付け忘れると、人が確認していないものが「決まったこと」に混ざる。これがこの道具で一番やってはいけないこと。
- **書かれていないことを足さない。** 推測で埋めたくなったら、埋めずに「未決」として登録する。
- **「決まった」と明言されていないものを決定にしない。** 誰も反対しなかっただけのものは未決。沈黙は合意ではない。
- 1件は1行で言い切れる大きさにする。1文に複数の話が入っていたら分ける。

## 手順

1. いまの状態を見る。重複登録を避けるため。

   ```sh
   ./bin/dandori.js list
   ./bin/dandori.js tree
   ```

2. 文章を読み、次のどれかに当てはまるものを拾う。どれにも当てはまらなければ拾わない。

   | 種類 | `--type` | 拾う目印 | 一緒に入れる項目 |
   |---|---|---|---|
   | まだ決まっていないこと | `open` | 「確認します」「持ち帰ります」、答えの出なかった問い、人によって言うことが違う点 | `--owner`（決める人。文中にあれば）`--due` |
   | 決めたこと | `decision` | 「〜とする」「〜に決定」と、誰かが明言したもの | `--owner` `--field reason=` `--field alternatives=`（出ていれば） |
   | 起きたら困ること | `risk` | 「〜だと困る」「〜かもしれない」 | タイトルは「〜した場合」の条件の形。`--field result=` `--field sign=` |
   | 言葉 | `term` | 人によって意味が違いそうな言葉、定義が語られた言葉 | `--field includes=` `--field excludes=` |
   | 要件 | `requirement` | 「〜できるようにしたい」 | `--field layer=`（下の表）。上の要件が分かれば `--parent R-n` |
   | 依頼 | `request` | 特定の人からの「〜してほしい」 | `--field problem=` `--field who=` `--field due_reason=` `--field workaround=` |

   要件の層：`purpose`（なぜやるのか）／`business`（誰が何をするのか）／`system`（システムが何を担うのか）／`function`（具体的に何ができるのか）。速さ・量・止まらなさの話は `--field level=yes` を足す。層に迷ったら `layer` を付けずに登録する（人が画面で選ぶ）。

3. 登録する。

   ```sh
   ./bin/dandori.js add "店舗受け取りの売上を、店舗と通販のどちらに計上するか" --type open --owner 社長 --ai
   ./bin/dandori.js add "店員が取り置き対象の一覧を見られる" --type requirement --field layer=function --parent R-4 --ai
   ```

4. 人に報告する。件数を種類ごとに1行ずつ。そのあと、**文章の中で気になったが登録しなかったこと**（発言が食い違っている箇所、主語のない決定など）を問いの形で伝える。最後に「画面の『今日やること』に確認待ちとして出ます」と添える。

## やらないこと

- 登録した案を自分で確認済みにしない（CLI にその手段はない。人が画面で行う）
- 既存の項目を、頼まれていないのに書き換えない
